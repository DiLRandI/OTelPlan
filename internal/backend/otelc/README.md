The adapter pins `otelc v1.1.0`. Other versions fail compatibility validation. Executable checks verify the reported version and compute a SHA-256 binary digest.

The capability map follows the pinned [hook API](https://github.com/open-telemetry/opentelemetry-go-compile-instrumentation/blob/v1.1.0/pkg/hook/context.go) and [trampoline implementation](https://github.com/open-telemetry/opentelemetry-go-compile-instrumentation/blob/v1.1.0/tool/internal/instrument/trampoline.go). Argument indexes in backend hooks include the receiver; OTelPlan indexes exclude it.

Generic targets are rejected because this backend disables parameter/result APIs, including context replacement. See [upstream issue 1280](https://github.com/open-telemetry/opentelemetry-go-compile-instrumentation/issues/1280). After hooks run through a deferred trampoline; the API does not expose the application panic value, so panic observation is not advertised.

Run the real executable identity check with `OTELPLAN_OTELC=/path/to/otelc go test ./internal/backend/otelc`. Generated instrumentation and trace correctness need separate end-to-end checks.

`RenderRules` converts a resolved plan into deterministic function-entry rules and stable before/after hook bindings. It preserves value/pointer receiver identity and rejects duplicate targets, inconsistent identities, and instrumentation of the generated hook package. Main-package targets require a verified isolated-build mapping and are currently rejected by generation.

`OTELPLAN_OTELC=/path/to/otelc go test ./internal/backend/otelc -run TestGeneratedRulesWithPinnedBackend` exercises generated rules through the real pinned compiler, verifying nested trace parentage and returned-error events. The test compiles generated lifecycle hooks with the race detector and exercises methods, explicit roots, nil contexts, disabled error recording, panic propagation, no-op telemetry, and concurrent calls. Compile/build CLI wiring remains separate work.

`RenderHooks` emits deterministic Go source for those bindings. Each invocation uses backend-local span state, replaces the selected context argument, records configured returned errors with a bounded status description, and ends the span on exit. The instrumentation scope is `otelplan.io/business` with the supplied runtime version. Nil context falls back to `context.Background`; explicit root mode starts a separate trace. No SDK or exporter is installed by generated hooks.

Lifecycle generation binds argument and constant attributes at entry and result attributes at exit, guarded by `span.IsRecording()`. Linker declarations connect the hooks to package-local helpers without importing application packages or triggering otherwise unused package initializers. Variadic targets remain rejected until typed signature generation is available. It fails without partial output, so captures are never silently omitted. The backend still cannot expose the application panic value; hooks end the span while preserving panic propagation.

`RenderAccessors` generates package-local helpers for explicit argument, result, and constant attributes. Discovery retains Go type expressions and import aliases so the helpers can assert private and imported named types. Each helper returns a primitive scalar and an availability flag; wrong types, nil pointer paths, unsigned values above `math.MaxInt64`, and non-finite floats are omitted. Zero, false, and empty string remain valid values. Generation enforces the existing default capture safety rules and emits no partial output on failure.

The private-accessor integration test compiles generated rules, helpers, and lifecycle hooks through the pinned backend with the race detector. It checks method argument offsets, private parameter types, nil omission, result and constant attributes, preserved return values, and an unused selected package whose initializer must not run. Emitting complete build artifacts remains separate work.

`RenderAccessorRules` returns exact package-level `add_file` rules and deterministic compile-only helper files for an importable provider package. The caller supplies the provider package stub and writes the returned files. Targets without captures need no helper; validation failures return no partial rules or files. The private-accessor integration test uses this output directly.

`RenderBundle` collects hooks, accessor helpers, provider source, and discoverable `*.otelc.yaml` rule files. Its `manifest.json` inventories payload paths and SHA-256 digests, with backend identity/capabilities, instrumentation version, and generated module path. The manifest does not hash itself; lock creation must also hash the returned manifest file. Rendering performs no filesystem writes or dependency changes. Executable verification, module preparation, and artifact publication remain caller responsibilities.

Bundles include a standalone Go 1.25 runtime module with pinned OpenTelemetry API and backend hook dependencies and checksums. No application SDK/exporter is installed. The private-accessor test loads this generated module alongside the application in a disposable workspace. Build orchestration must still verify that workspace dependency selection preserves the analyzed application graph.
